피드백 내용

섭취량 반영
 - 먹은 양·마신 양을 반영해야 공정하지 않나
 - 누가 얼마나 먹었는지 세기 어렵다
 - 한 입만 먹고 오래 앉아 있거나, 잠깐 있다가 많이 먹는 예외는?

입력 부담
 - 시작 시간·음주 여부 체크로 총무 일이 늘어난다
 - 자동 반영보다 직접 입력이 많다

사용 동기
 - 실제 송금 없이 계산만 해줘서 쓸 이유가 약하다

근거 부족
 - N빵이 불공정하다는 전제를 뒷받침할 수요 데이터가 없다
 - '공정'의 정의가 없다 (수식이 만족하는 성질이 명시되지 않음)
 - 평가 계획이 없다 (추출 정확도, 정산 결과 납득도 측정 방법 없음)
 - 기존 서비스(토스·카카오페이 정산, Splitwise 등) 대비 차별성 근거가 없다

신뢰성
 - 영수증 사진을 저장하지 않아 문제가 생겨도 검토할 수 없다

개인정보
 - Gemini API 사용에 따른 개인정보 침해 우려

서비스 범위
 - 포인트 적립 · 현금영수증 처리는?
 - 주류회사에 제안할 수 있나

계산 로직
 - 원 단위 반올림 시 개인 부담액 합이 총액과 어긋난다
 - 할인·서비스(0원)·봉사료 등 특수 항목 처리 규칙이 없다
 - 음주자 0명인데 술 항목 존재, 참석 시간 전원 0 등 예외에서 0으로 나누기 발생
 - 시간 동안 균등하게 소비한다고 가정한다 (메인 안주는 초반에 몰림)
 - 술 종류(소주/맥주)를 구분하지 않는다
 - 하이볼·음료수·소맥 등 분류 기준이 모호하다

기능 공백
 - 1차·2차 등 영수증 여러 장, 결제자 여러 명을 처리하지 못한다
 - 참여자 확인 기능을 넣으면 전원 앱 설치가 필요해진다

기술 신뢰성
 - Gemini 추출 결과(금액 오인식, 없는 항목 생성)를 검증하는 장치가 없다
 - 모임 코드가 짧으면 타인이 모임 정보에 접근할 수 있다
